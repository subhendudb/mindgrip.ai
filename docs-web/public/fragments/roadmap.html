Roadmap

Key Steps to Build Your Sorting Robot

Follow these 9 phases end-to-end — from zero hardware to an autonomous pick-and-place robot — on your laptop/desktop (8–16 GB) or Raspberry Pi control host. After assembly, prefer LeLab on a laptop/desktop for calibrate → teleop → record → train (cloud) → deploy; use CLI on Pi or when you need full control. See Host Computer for Plans A–C. Click a step to expand or collapse its details.

1

Install Software & Dependencies

Software

Install the MindGrip stack on your control host (laptop/desktop 8–16 GB or Raspberry Pi 64-bit). Full inventory: Software on the project page. Prefer uv everywhere; run tools with uv run ….

  • Prerequisites: Git · uv · Python 3.12+ (via uv, not system Python).
  • LeRobot (core): clone sibling to this overlay · sync with feetech + hardware + viz extras.
  • so101-lab (this repo): CLI menu, plugins, patches, docs — checkout next to lerobot/.
  • Path A — LeLab (GUI): laptop/desktop · uv tool install git+https://github.com/huggingface/leLab.git · see LeLab guide / #lelab.
  • Path B — CLI: any host (prefer on Pi) · ./so101_cli_menu.sh · see CLI menu / #cli-menu.
  • Linux / Pi: add user to dialout for USB serial (not needed on macOS).
  • Disk: aim for 60–80+ GB free before long recording.
  • Later (Step 8): hf auth login for Hub push / HF Jobs — not required to finish install.
  • Optional later: MuJoCo sim — Optional Tooling · not needed for Steps 6–9.

#   temp/so101-lab/   ← this MindGrip overlay

# 3b) Terminal path (any host — prefer on Pi)

2

Program Motor IDs

Hardware

Every Feetech motor ships with ID = 1. Program each motor one at a time (unique IDs 1–6 + baud 1 Mbps) before daisy-chaining. Prefer the project CLI menu; raw commands are shown below for reference.

CLI menu — try this first

From the repo root run ./so101_cli_menu.sh (config in .so101_cli.env). Full option map: CLI Command Menu.

  • 0 · Find USB ports — discover leader / follower /dev/tty… (or use menu C to save ports).
  • 3 · Program motor ID — wraps set_middle_positions.py: pick leader or follower, then ID 1–6. Connect ONLY that motor → script sets ID + baud → holds ~2047 → attach horn/link → Enter.
  • 4 · Setup motors — wraps official lerobot-setup-motors (guided plug-in order for leader so101_leader or follower so101_follower). Same one-motor-at-a-time rule.
# From so101-lab/
./so101_cli_menu.sh
# → 0  find ports  ·  3  program ID  ·  4  setup motors (official helper)
🧭
3 vs 4: Option 3 is this kit’s middle-position helper (good when assembling horns at neutral). Option 4 is Hugging Face’s stock setup flow. Use either path; do not daisy-chain until all six IDs exist on that arm. Deep links: CLI · 0 · CLI · 3 · CLI · 4.

If you use LeLab

LeLab’s strength is calibrate → teleop → record → train → deploy. Motor ID programming is still a CLI / workshop step — LeLab does not replace options 0 / 3 / 4 above. Recommended sequence when you prefer the GUI afterward:

  1. Finish IDs with ./so101_cli_menu.sh → 0 then 3 and/or 4 (leader 5 V, follower 12 V separately).
  2. Assemble joints at neutral while each motor holds ~2047 (Step 3).
  3. Launch lelab on a laptop/desktop → Add robot (leader + follower), pick the same USB ports, set id LeoArm for both.
  4. In LeLab, run guided Calibrate (Step 4) — Status stays Idle until Start; Find Port only detects USB.
  5. Continue Teleop / Record in LeLab. Details: LeLab for MindGrip AI · #lelab.
ℹ️
Official motor setup docs (same idea as menu 4): SO-101 · Set motor IDs. LeLab overview: LeLab guide.
  • Example ports (this kit): leader /dev/tty.usbmodem5AE60832361 · follower /dev/tty.usbmodem5B141118901 — re-check with menu 0 if they change.
  • Before daisy-chaining: unique IDs 1–6 must already be programmed (one motor at a time).
⚡
Power — do not mix: Leader motors → 5 V · Follower motors → 12 V · USB is data only (not motor power). Never swap PSUs. Confirm LED/bus after PSU-on, then plug USB.

Assemble at Neutral Positions

Hardware

Joint links were attached during Step 2 while each motor held ~2047. Never attach a horn off-middle — the software zero will be mechanically offset and the arm can damage itself.

  • Leader ≠ follower motors/gears — use the correct STS3215 variant per joint (leader 5 V vs follower 12 V kits).
  • Install 3-pin cables before closing links; daisy-chain from shoulder_pan (ID 1) → board.
  • Base mount + camera stand on follower only (leader is teleop input).
  • 3D prints are fragile — dry-fit, do not overtighten; verify free motion before powering motors.
  • Leader: /dev/tty.usbmodem5AE60832361 · Follower: /dev/tty.usbmodem5B141118901
  • Procedure: run helper → motor holds middle → slide horn on → lock set screw → press Enter.
  • Never force a joint past its mechanical stop.

4

Calibrate Both Arms

Hardware

Calibration records each joint's encoder range_min / range_max and homing offset. Runtime uses that JSON to convert ticks → degrees so leader and follower report the same values in the same pose. Prefer LeLab on a laptop/desktop; use the CLI menu on Pi or when you want full terminal control.

⚠️
This step is critical. Incomplete or skipped calibration is the most common cause of bad teleop, lag, and failed demos later. Sweep every joint through its full mechanical range (including wrist roll and gripper), then Save. Do not continue to Step 5 until both arms have a saved LeoArm.json.
✅
Bring-up before calibrate: Power PSU first, then USB · confirm LED/bus · separate ports for leader & follower · power the arm before expecting Status / calibration in LeLab. Use id LeoArm for both arms.

LeLab — preferred path (laptop/desktop)

After motor IDs and assembly (Steps 2–3), calibrate in the GUI. Guide: LeLab for MindGrip AI · HF · LeLab.

  1. Launch lelab · Add robot for leader (teleoperator) and follower (robot).
  2. Select the correct USB ports (Find Port if needed) · set id LeoArm for both arms.
  3. Open Calibrate for one arm at a time · put all joints mid-range before Start.
  4. Click Start → sweep each joint through its full mechanical range (Status: Recording Ranges).
  5. Aim for green ticks (~98% of target span) · then Save Calibration (Cancel / Stop / leave page discards the session).
  6. Repeat for the other arm · then proceed to teleop (Step 5).
  • Status Idle until Start — Find Port only detects USB, not live motor reads.
  • Writes under $HF_LEROBOT_HOME/calibration/…/LeoArm.json (typically ~/Documents/lerobot).

CLI menu — try this on Pi or without LeLab

From the repo root: ./so101_cli_menu.sh (ports / ids in .so101_cli.env — menu C to edit). Full map: CLI Command Menu.

  • 5 · Calibrate leader — wraps lerobot-calibrate --teleop.type=so101_leader … --teleop.id=LeoArm → teleoperators/so_leader/LeoArm.json.
  • 6 · Calibrate follower — wraps lerobot-calibrate --robot.type=so101_follower … --robot.id=LeoArm → robots/so_follower/LeoArm.json.

Verify with Live Teleoperation

Software

Before collecting training data, confirm everything works end-to-end: leader movements should be mirrored by the follower in real time with no lag or joint slipping. Prefer LeLab on a laptop/desktop; use the CLI menu on Pi or when you want full terminal control.

LeLab — preferred path (laptop/desktop)

Guide: LeLab for MindGrip AI · HF · LeLab.

  1. Confirm both arms are calibrated and saved as id LeoArm (Step 4).
  2. Attach the USB camera on the follower (Robot) only — not the leader (Teleoperator).
  3. In LeLab, open Teleoperation with leader + follower connected.
  4. Move the leader slowly through each joint — follower should mirror smoothly with no lag or slipping.
  5. Open the right Cameras panel and toggle On for the live preview (off by default; needs follower cameras configured).
  6. If lag or mismatch appears, fix calibration / cabling before recording — see Troubleshooting.
📷

6

Set Up the Sorting Scene

Hardware

Design a consistent tabletop workspace before collecting demonstrations. Consistency is critical — the policy generalises from what it sees, so the scene must stay fixed.

Camera & workspace layout

One fixed USB camera on a stand, aimed at the follower workspace (not on the leader, not on moving links). Software name: front · 640×480 @ 30 FPS · keep the same angle for every record and ACT rollout.

📐
Kinematics helps scene design. Use forward / inverse kinematics to size the workspace so bins and pick zones stay inside the follower’s reach. A useful bound is Lmax ≈ 38 cm (approximate max reach of the SO-101 arm) — keep the taped mat (~30 × 30 cm) and both bins well inside that arc, not at the edge of singularity or overstretch. Learn the equations and interactive demo: Forward & Inverse Kinematics.
  • Workspace boundary: Use tape or a mat to mark the reachable area (≈ 30 × 30 cm in front of the follower base) — inside Lmax.
  • Object placement: Define a source / pick zone and two labelled bins: match-box bin and reject bin.
  • Camera mount: Fixed stand in front of / above the workspace · ~30–45° down · same pose every session. Attach the camera to the follower in software (front), not on moving links. Do not use a laptop FaceTime camera as the policy view.
  • Lighting: Stable, diffuse lighting — avoid strong shadows or reflections on objects.
  • Objects: Match-boxes (or clear match-box proxies) plus a varied set of “other” objects that fit the gripper. Keep sizes easy to grasp.
💡
Pro tip: 3D-print or purchase bins with chamfered openings. The extra tolerance makes early ACT evaluations far more forgiving. Keep the match-box visually distinct from reject objects.
7

Collect Demonstration Data

Data

Capture teleoperated episodes into a LeRobot-format dataset (HuggingFace compatible). Each episode records joint positions, velocities, camera frames, and timestamps. Prefer LeLab on a laptop/desktop; use the CLI menu on Pi or when you want full terminal control.

  • Target ~40–50 episodes per class (~80–100 total), balanced between match-box and other objects.
  • Vary the starting position of objects slightly across episodes to improve generalisation.
  • Use the project task string for every episode (see Overview).
  • Scene + camera pose must match Step 6 for every session (same front view).
🤗
Example dataset (this lab): SUBHENDU/pick_place_sorting_20260911_184643 · Hub dataset · LeRobot dataset visualizer. When you record, LeRobot often stamps a timestamp onto pick_place_sorting — use your stamped id for viz / train.

8

Train an Imitation Learning Policy

ML Training

Train a neural policy that maps visual observations and joint states to motor commands by imitating your recorded demonstrations. Prefer LeLab → HF Jobs on a laptop/desktop; use the CLI menu on a CUDA host (or when you want full terminal control). Full comparison (with / without USB camera): Policy Cheatsheet.

Recommended
ACT
Action Chunking Transformer. Fast training, great on pick-and-place with short demos.
Recommended
Diffusion Policy
Denoising diffusion for smooth, multi-modal action generation. Better generalisation.
Advanced
SmolVLA
Vision-Language-Action model. Requires task language prompts; strongest on varied tasks.
Explore
Pi-0 / Pi-0 Fast
Flow-matching diffusion transformer. State-of-the-art but compute-intensive.
🤗
Example ACT run (this lab): dataset SUBHENDU/pick_place_sorting_20260911_184643 → trained model SUBHENDU/act_2026-09-11_13-54-04 · 10k steps · HF Jobs a10g-small · final loss ≈ 0.21.
⚠️
Low-RAM hosts (8–16 GB laptop/desktop or Pi): Do not plan on comfortable local training. Prefer ACT on a cloud NVIDIA GPU after pushing the dataset to the Hub. Recommended AWS: g5.xlarge / g5.2xlarge (1× A10G ~24 GB) or g6.xlarge (1× L4 ~24 GB); budget ACT-only: g4dn.xlarge (T4 16 GB). Or use LeLab → HF Jobs flavor a10g-large / a10g-small. Local CPU/MPS ACT is tiny-experiments only. Diffusion / SmolVLA / Pi-0 are not practical on these hosts.

LeLab — preferred path (laptop/desktop → HF Jobs)

Guide: LeLab for MindGrip AI · HF · LeLab. Run training in the cloud from the app — not on the control laptop/Pi.

  1. Confirm the dataset from Step 7 is on the Hub (example: SUBHENDU/pick_place_sorting_20260911_184643).
  2. In LeLab, open Training, select the dataset, policy type ACT, and a GPU flavor (e.g. a10g-small / a10g-large).
  3. Start the job and watch progress (steps, loss, learning rate, logs). Typical ACT run: ~10k steps on ~50 episodes.
  4. When status is done, open View on Hub — LeLab pushes the checkpoint automatically.
  5. Copy the model repo id for Step 9 rollout (example: SUBHENDU/act_2026-09-11_13-54-04).

Support

Troubleshooting

Common SO-101 faults and leader–follower teleop sync issues — kept here so you do not need a separate checklist page.

Hardware & bus

Input voltage error

External PSU off/disconnected. Turn 12 V (follower) / 5 V (leader) ON, reseat daisy-chain cables, power-cycle, retry.

Overload error

Joint hit a hard stop or was blocked. Move the joint free by hand, power-cycle to clear the fault flag, retry. Blinking motor LEDs usually mean overload or wrong supply voltage for that motor variant.

No status packet

Bus communication break (loose JST cable). Check connectors up to the last responding motor ID, power-cycle.

Motor not found

set_middle_positions.py / setup-motors cannot see the servo. Confirm cable, correct macOS /dev/tty.usbmodem… port, and clear overload by power-cycle.

USB disconnect / intermittent freezes

Prefer short quality USB; avoid unpowered hubs. Confirm ports with menu 0. Intermittent jumps → power, cables, or motor faults in the logs first.

Swapped motor IDs

IDs must match joints: 1 shoulder_pan · 2 shoulder_lift · 3 elbow_flex · 4 wrist_flex · 5 wrist_roll · 6 gripper. Wrong ID → only that joint “mirrors” wrongly in teleop.

Calibration & LeLab

Calibration mismatch

Motor replaced or reassembled since last JSON. Type c at the prompt, or re-run lerobot-calibrate / LeLab calibrate with id LeoArm for both arms from the same mid-range pose.

Constant pose offset (even when still)

Leader and follower disagree at rest. Recalibrate both from a shared mid pose; confirm both use id LeoArm and full ROM sweep completed before Save.

Stops short at travel ends

Calibration did not cover full range of motion. Redo follower + leader calib; move each joint through its full travel when prompted.

LeLab Status empty / no ticks

Arm powered? Correct leader port …5AE60832361? Badge must be Recording Ranges. Green ticks are optional — click Save Calibration before Cancel. Cancel discards results.

Wrong leader/follower port in LeLab

Find Port can attach the wrong adapter. Leader = …5AE60832361, follower = …5B141118901. Swap → sync/calibration looks broken.

invalid choice: so101_follower

Wrong flag prefix. Leader → --teleop.type=so101_leader. Follower → --robot.type=so101_follower.

Teleop sync (leader → follower)

Tracks slow, lags on fast moves

Often normal bus/control lag. Slow the leader; first-test without cameras / Rerun; keep loop near target FPS. If still bad, check USB load and power.

Only one joint wrong

Isolate that joint: recheck motor ID, that joint’s calibration sweep, and free motion by hand (binding / crash). Gripper alone → check open/close direction and range.

Chopping / low loop rate

Display or camera overload. Disable --display_data, lower camera resolution, use MJPG, better USB path. Confirm use_degrees matches on leader and follower (default true).

Before changing many things

Order: power & cables → correct ports → mid-pose recalibrate both → teleop with no camera → then add cam. Do not tune many software flags at once.
