SO-101 Policy Cheatsheet

Quick guide to which LeRobot policy to pick for the SO-101 arm — especially the pick & place sorting project — with or without a USB camera.

TIP: For color / shape / category sorting on a tabletop SO-101, start with ACT + one fixed USB camera. Use this page when you outgrow that or want a VLA.

See also: Acronyms glossary · Commands cheat sheet · Compute Hardware Guide

60-second decision (SO-101 sorting)

Your situation Pick Why
First sorting robot, USB cam, MacBook Air + cloud GPU ACT Fast to train, data-efficient (~50 demos), light compute
Same setup, want smoother / multi-modal motions Diffusion Policy Better when demos have several valid ways to grasp/place
Multiple spoken/written task variants (“put red in left bin”) SmolVLA Small VLA; needs language in the dataset task field
Foundation-model / research, big cloud GPU π₀ / π₀.₅ / π₀-FAST Strong generalist VLAs; heavy train + fine-tune
No USB camera Don’t train a vision sorter Color/shape sorting needs pixels. Use teleop/replay only, or add a camera

Without a USB camera: policies below that list “vision required” will not solve visual sorting. Joint-only control can still be used for hardware checks (lerobot-teleoperate, lerobot-replay), but autonomous sorting needs a camera.

Legend

Label Meaning
With USB cam Best fit when you have a fixed overview webcam (640×480 @ 30 FPS is enough for color sorting)
Without USB cam What you can still do; usually not visual pick-and-place
Compute Rough training class (see hardware guide)
SO-101 fit How well it matches the sorting project on MacBook Air + cloud

Policy cards

ACT — Action Chunking Transformer

Type Lightweight imitation / behaviour cloning
One-liner Predicts short chunks of future joint actions from images + robot state.
With USB cam Best default for SO-101 color/shape sorting, pick-to-bin, simple recycling demos.
Without USB cam Config expects image features — not a practical sorter. Use for teleop/hardware only.
Compute Light (~2–6 GB VRAM) · cloud: AWS g5 / HF a10g-large
SO-101 fit ★★★★★ first policy
Docs ACT 
lerobot-train --policy.type=act --dataset.repo_id=USER/pick_place_sorting ...

Diffusion Policy

Type Denoising diffusion over action sequences
One-liner Learns a distribution of actions — good when demos are multi-modal (several valid grasps).
With USB cam Strong for sorting when trajectories vary a lot; smoother than plain BC.
Without USB cam Vision-oriented in typical SO-101 setups — skip for visual sorting.
Compute Medium (~8–14 GB) · same A10G/L4 class, longer than ACT
SO-101 fit ★★★★ after ACT works
Docs Policy type diffusion in train CLI · hardware guide 
lerobot-train --policy.type=diffusion --dataset.repo_id=USER/pick_place_sorting ...

SmolVLA — Small Vision–Language–Action

Type Small VLA (vision + language → actions)
One-liner Fine-tune a compact foundation policy with camera views, state, and a text instruction.
With USB cam Best when one arm must switch tasks via language (“red bin” vs “blue bin”) without separate ACT models.
Without USB cam Needs vision (+ language). Empty-camera tricks exist for missing extra views, not zero cameras.
Compute Small VLA (~10–16 GB) · A10G/L4 OK; slower than ACT
SO-101 fit ★★★★ multi-instruction sorting
Docs SmolVLA

π₀ (Pi0)

Type Large flow-matching VLA
One-liner Generalist vision–language–action model; fine-tune for your SO-101 tasks.
With USB cam Research / advanced: few-shot transfer, rich language, varied objects.
Without USB cam Not for camera-less sorting.
Compute Large VLA (~24–40 GB) · prefer A100-class
SO-101 fit ★★ explore after ACT/SmolVLA
Docs π₀

π₀-FAST (Pi0Fast)

Type Faster-token π₀ family variant
One-liner π₀-style VLA with FAST action tokenization for snappier inference.
With USB cam When you want π₀-class generality with better runtime on the robot.
Without USB cam Vision + language required.
Compute Large VLA
SO-101 fit ★★ advanced
Docs π₀-FAST

π₀.₅ (Pi05)

Type Later π-family VLA
One-liner Stronger π-series policy for open-world / language-conditioned control.
With USB cam Advanced multi-task sorting, research demos.
Without USB cam Not applicable for visual sorting.
Compute Large VLA · A100+ recommended
SO-101 fit ★★ research
Docs π₀.₅

Multitask DiT

Type Diffusion / flow Transformer + CLIP vision/text
One-liner Language-conditioned multitask diffusion policy.
With USB cam Several related sorting tasks in one model (different objects/bins via text).
Without USB cam Relies on vision + language — not camera-less.
Compute Diffusion class (~8–14 GB+) · inference likes a strong GPU
SO-101 fit ★★★ multi-task sorting
Docs Multitask DiT

X-VLA

Type Cross-embodiment VLA
One-liner Pretrained across robots/cameras; adapt with domain IDs and rename maps.
With USB cam When reusing Hub checkpoints and mapping front → expected image keys.
Without USB cam Expects image views (can pad with empty cameras if a checkpoint wants more views than you have).
Compute Large VLA
SO-101 fit ★★ advanced transfer
Docs X-VLA · Rename map

EO-1

Type VLM backbone + flow-matching action head
One-liner Conversation-style vision–language–state → continuous actions.
With USB cam Language-driven SO-101 tasks; needs task text in data.
Without USB cam Vision required.
Compute Large / multimodal
SO-101 fit ★★ explore
Docs EO-1

MolmoAct2

Type Vision–language–action
One-liner Molmo-based act policy for grounded visual instructions.
With USB cam Instruction-following pick/place when you have GPU headroom.
Without USB cam Vision required.
Compute Heavy (benchmarks often on H100-class)
SO-101 fit ★★ research
Docs MolmoAct2

NVIDIA GR00T N1.5

Type Large multimodal robot foundation model
One-liner NVIDIA’s generalist humanoid/manipulation stack in LeRobot.
With USB cam Heavy research; overkill for simple 3-bin color sort.
Without USB cam Not a camera-less sorter.
Compute Multimodal large (~24–40 GB+)
SO-101 fit ★ curiosity / research
Docs GR00T

WALL-OSS

Type Embodied multimodal / VLA-style
One-liner Large vision–language–action pretrained policy family.
With USB cam Advanced open-world manipulation experiments.
Without USB cam Vision required.
Compute Large VLA
SO-101 fit ★ research
Docs WALL-OSS

VQ-BeT

Type Vector-quantized behaviour transformer
One-liner Discrete latent actions + transformer; light BC family.
With USB cam Alternative light policy for vision+state demos (often single cam).
Without USB cam Still expects an image key in config — not for sorting without cam.
Compute Light (~2–6 GB)
SO-101 fit ★★★ alternative to ACT
Docs Policy type vqbet

TDMPC

Type Model-based / MPC-style learning
One-liner Planning with a learned dynamics model (often sim / RL-flavoured setups).
With USB cam Niche for SO-101 tabletop IL sorting — prefer ACT first.
Without USB cam Possible in state-based control loops; not the path for visual bin sorting.
Compute Light class, config-dependent
SO-101 fit ★ special cases
Docs Policy type tdmpc · see RL guides for related workflows

Use-case → policy (sorting project scenarios)

SO-101 use case With USB camera Without USB camera
Color-based sorting (3 blocks → 3 bins) ACT (start) → Diffusion if needed Not solvable visually — add camera
Shape-based sorting ACT or Diffusion Same — needs vision
Recycling / warehouse pick-to-bin ACT; SmolVLA if bins chosen by text Teleop only
Produce grading / defect markers ACT / Diffusion; VLA if instructions vary Needs vision
One model, many verbal tasks SmolVLA or Multitask DiT Needs cam + language in demos
Hub pretrained → your SO-101 X-VLA / π-family + rename map Still need at least the views the checkpoint expects
Hardware bring-up only Any — prefer no train yet Teleop + replay (no policy)

MacBook Air reminder

  • Record & deploy on the Air with USB cam.
  • Train on cloud (NVIDIA A10G/L4 or HF Jobs; AMD ROCm possible but more DIY).
  • Prefer ACT until sorting succeeds; then try Diffusion or SmolVLA.
