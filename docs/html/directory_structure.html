Repository Directory Structure

This page maps the LeRobot application layout: what each top-level folder is for, what lives under src/lerobot/, and which root files matter day to day.

Note: The docs/ tree is summarized only (no full file list). Browse the sidebar for all HTML chapters, or open docs/source/ for Hugging Face MDX sources.

Top-level tree

lerobot/
├── src/lerobot/          # Python package (library + CLI)
├── tests/                # Pytest suite
├── examples/             # End-user scripts & notebooks
├── docker/               # Docker images (user, CI, benchmarks)
├── docs/                 # Documentation (MDX + local HTML site)
├── images/               # Photos used by the SO-101 setup guide
├── media/                # Media assets
├── scripts/              # Extra helper scripts (repo root)
├── .github/              # CI workflows, issue/PR templates
├── pyproject.toml        # Deps, extras, CLI entry points, tool config
├── uv.lock               # Locked dependency versions (uv)
├── Makefile              # E2E / make targets
├── README.md             # SO-101 setup & teleoperation guide (this fork)
├── set_middle_positions.py
├── start.sh              # Serve local HTML docs
├── control_arm.py
└── test_arm.py

Top-level folders

Folder Purpose
src/ Installable Python package. Everything under src/lerobot/ is the library you import and the CLIs you run (lerobot-train, lerobot-record, …).
tests/ Automated tests (unit, integration, hardware-skipped). Fixtures in tests/fixtures/, mocks in tests/mocks/.
examples/ Copy-pasteable tutorials: training, datasets, phone teleop, OMX, LeKiwi, RTC, notebooks, etc.
docker/ Container images: CPU (Dockerfile.user), GPU (Dockerfile.internal), and per-sim-benchmark eval images (Dockerfile.benchmark.*). See detailed docker/ section below.
docs/ Human documentation. docs/source/ = Hugging Face MDX; docs/html/ = local browsable site; helpers build_html.py, serve_html.py.
images/ Assembly / teleop photos referenced by the SO-101 setup guide.
media/ Additional media assets for docs or demos.
scripts/ Repo-level helper scripts (outside the packaged CLI).
.github/ GitHub Actions CI (quality, tests, security, release), issue/PR templates.

docs/ (summary only)

Path Purpose
docs/source/ Official doc pages (.mdx / .md) + _toctree.yml sidebar order.
docs/html/ Generated static HTML for local browsing (./start.sh).
docs/build_html.py Converts docs/source → docs/html.
docs/serve_html.py Local HTTP server for docs/html.
docs-requirements.txt Extra packages for Hugging Face doc-builder (upstream site build).

Do not treat docs/html/ as hand-edited source — rebuild it with uv run python docs/build_html.py.

src/lerobot/ — package layout

src/lerobot/
├── scripts/           # CLI entry points (train, eval, record, teleoperate, …)
├── configs/           # Dataclass configs (draccus); TrainPipelineConfig, policies, …
├── policies/          # Policy implementations (ACT, SmolVLA, π0, …)
├── processor/         # Observation/action transform pipelines
├── datasets/          # LeRobotDataset + Hub/video helpers
├── envs/              # Simulation env configs & factories
├── robots/            # Real robot drivers (SO-101, Koch, LeKiwi, …)
├── teleoperators/     # Leader arms, phone, keyboard, …
├── motors/            # Low-level motor buses (Feetech, Dynamixel, …)
├── cameras/           # OpenCV, RealSense, etc.
├── optim/             # Optimizers / schedulers
├── model/             # Shared model building blocks
├── rl/                # Reinforcement learning utilities
├── rewards/           # Reward models
├── async_inference/   # Async policy inference
├── rollout/           # Deployment / rollout helpers
├── transport/         # Client/server transport for remote inference
├── transforms/        # Data transforms
├── data_processing/   # Dataset processing utilities
├── templates/         # Model card templates
├── utils/             # Shared helpers
├── common/            # Common constants/helpers
├── types.py           # Core type aliases
└── __version__.py
Subfolder / file Purpose
scripts/ Implements CLIs mapped in pyproject.toml → lerobot-train, lerobot-eval, lerobot-record, lerobot-teleoperate, lerobot-calibrate, …
configs/ Typed configs for training, policies, robots, datasets. Choice registries select policy/robot types from CLI flags.
policies/ One subdirectory per policy; each inherits PreTrainedPolicy and can push/pull from the Hub.
processor/ Chains of ProcessorSteps between dataset ↔︎ policy ↔︎ robot.
datasets/ Episode-aware datasets, video decoding, Hub sync.
envs/ Gymnasium-style sim environments (PushT, LIBERO, MetaWorld, …).
robots/ Hardware robots (followers): SO-100/101, Koch, Hope Jr, Reachy, …
teleoperators/ Input devices / leader arms used to control robots.
motors/ Servo bus communication (IDs, baud, read/write positions).
cameras/ Camera backends used during teleop and recording.
rl/, rewards/ RL training loops and reward-model support (e.g. HIL-SERL).
async_inference/, rollout/, transport/ Serving and running policies (including remote/async setups).

tests/

Area Purpose
tests/<module>/ Mirrors package areas (policies, datasets, robots, …).
tests/fixtures/ Shared pytest fixtures.
tests/mocks/ Fake hardware / lightweight stand-ins.
tests/artifacts/ Test data (often via Git LFS).
tests/utils.py, conftest.py Skip helpers for hardware, shared setup.

Run: uv run pytest tests -svv --maxfail=10

examples/

Subfolder Purpose
tutorial/, training/ Learning paths and training examples.
dataset/, port_datasets/ Creating and porting datasets.
phone_to_so100/, so100_to_so100_EE/, lekiwi/, omx/ Hardware-specific demos.
rtc/, backward_compatibility/ Advanced / migration examples.
notebooks/ Jupyter notebooks (also linked from docs).

docker/

Container images for running LeRobot without installing every native dependency on your host. Nightly builds from main are also published to Docker Hub (huggingface/lerobot-cpu, huggingface/lerobot-gpu).

Layout

docker/
├── README.md                         # How to pull / build / run images
├── Dockerfile.user                   # CPU image (explore, robots, light use)
├── Dockerfile.internal               # GPU image (training, CI)
├── Dockerfile.benchmark.libero       # Sim eval: LIBERO
├── Dockerfile.benchmark.libero_plus  # Sim eval: LIBERO+
├── Dockerfile.benchmark.metaworld    # Sim eval: Meta-World
├── Dockerfile.benchmark.robocasa     # Sim eval: RoboCasa
├── Dockerfile.benchmark.robocerebra  # Sim eval: RoboCerebra
├── Dockerfile.benchmark.robomme      # Sim eval: RoboMME
├── Dockerfile.benchmark.robotwin     # Sim eval: RoboTwin
└── Dockerfile.benchmark.vlabench     # Sim eval: VLABench

Core images (general use)

File Role Base / notes
Dockerfile.user Lightweight CPU image for exploring the codebase, running scripts, or working with robots. Not meant for serious GPU training. python:3.12-slim → published as huggingface/lerobot-cpu
Dockerfile.internal GPU / CUDA image used for training and CI. Batteries-included environment matching Hugging Face’s GPU workflows. nvidia/cuda → published as huggingface/lerobot-gpu

Typical pull/run:

docker pull huggingface/lerobot-cpu:latest
docker pull huggingface/lerobot-gpu:latest

docker run -it --rm huggingface/lerobot-cpu:latest
docker run -it --rm --gpus all --shm-size 16gb huggingface/lerobot-gpu:latest

USB robots/cameras from a container (example):

docker run -it --device=/dev/ -v /dev/:/dev/ --rm huggingface/lerobot-cpu:latest

Benchmark images (Dockerfile.benchmark.*)

These are not for SO-101 teleoperation. They are pre-baked evaluation images for simulation benchmarks.

Each sim suite (LIBERO, MetaWorld, …) needs heavy native deps (MuJoCo, scene assets, extra Python packages). Installing them on a laptop is fragile. Each Dockerfile.benchmark.*:

  1. Starts from huggingface/lerobot-gpu:latest
  2. Pre-downloads that benchmark’s assets/config into the image (so CI/runtime does not fetch them live)
  3. Copies this repo’s source on top
  4. Lets you run lerobot-eval in a reproducible environment
File Benchmark What it is for
Dockerfile.benchmark.libero LIBERO Lifelong / manipulation task suite used for policy eval
Dockerfile.benchmark.libero_plus LIBERO+ Extended LIBERO variant
Dockerfile.benchmark.metaworld Meta-World Multi-task MuJoCo manipulation benchmark
Dockerfile.benchmark.robocasa RoboCasa Large-scale kitchen / household simulation
Dockerfile.benchmark.robocerebra RoboCerebra Simulation benchmark environment
Dockerfile.benchmark.robomme RoboMME Multi-modal evaluation suite
Dockerfile.benchmark.robotwin RoboTwin Dual-arm / twin-robot simulation tasks
Dockerfile.benchmark.vlabench VLABench Vision-language-action benchmark

Example (LIBERO):

docker build -f docker/Dockerfile.benchmark.libero -t lerobot-bench-libero .
docker run --gpus all --rm -it \
  -v $HOME/.cache/huggingface:/root/.cache/huggingface \
  lerobot-bench-libero \
  lerobot-eval --policy.path=<your_policy> --env.type=libero --eval.n_episodes=50

When to use which

Goal Use
Explore code / CPU scripts / robot USB access Dockerfile.user / lerobot-cpu
Train policies on GPU Dockerfile.internal / lerobot-gpu
Score a policy on a sim benchmark Matching Dockerfile.benchmark.*
SO-101 assemble / calibrate / teleop on bare metal No Docker required — follow SO-101 Pick & Place Sorting

More detail: docker/README.md in the repo, and the Benchmarks section in the sidebar (LIBERO, Meta-World, …).

LICENSE Project license.

Quick mental model

  1. Control & data collection → robots/, teleoperators/, cameras/, motors/ + CLIs in scripts/
  2. Learn a policy → datasets/ + policies/ + lerobot-train
  3. Evaluate → sim envs/ or real robot via lerobot-eval / lerobot-record with --policy.path
  4. Docs & onboarding → docs/ (this site) and examples/
