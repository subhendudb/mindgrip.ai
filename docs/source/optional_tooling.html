Why these exist

Purpose in the overall project

MindGrip’s milestone is a learned match-box vs reject sorter on physical SO-101. MuJoCo fills gaps around that milestone — practice and pipeline dry-runs — without replacing real demos or ACT.

Tool Role in MindGrip Required for Steps 6–9?
MuJoCo SO-101 plugin Simulated follower for pipeline practice, leader dry-runs, algorithm tests — without moving the real arm No
Keyboard teleop plugin Drive sim (or headless) when no leader arm is available No
LeRobot core patches Optional recording / camera UX on sibling lerobot/ No — orthogonal to MuJoCo / keyboard
⚠️
Sim ≠ sorter. Policies trained only in MuJoCo will not transfer cleanly to the physical arm + USB cam. Use real demos for the binary sorter (Step 7 → Step 9).

MuJoCo and keyboard plugins are installable today from this overlay. Roadmap Step 1 already shows the same uv pip install -e lines as optional.

Canonical install (from so101-lab root)

# After sibling lerobot is installed into this .venv
uv pip install -e packages/lerobot_robot_so101_mujoco
uv pip install -e packages/lerobot_teleoperator_so101_keyboard

# Or let the CLI do it:
./so101_cli_menu.sh 18   # ensure MuJoCo + keyboard plugins
ℹ️
Prefer these editable installs over any older uv sync --extra so101-mujoco note — that extra is not defined in this overlay’s pyproject.toml.

Patches (orthogonal)

# Only if you want recording / camera UX tweaks on sibling lerobot — not for sim
./scripts/apply_lerobot_patches.sh ../lerobot

Details: patches/README.md.

SO-101 MuJoCo modes

Simulated follower registered as --robot.type=so101_mujoco, id sim_follower. Sim camera key front (640×480) mirrors the lab USB overview cam.

Quick starts

CLI · 16 / 17 / 18

./so101_cli_menu.sh 18   # install plugins once
./so101_cli_menu.sh 16   # Control-slider viewer
./so101_cli_menu.sh 17   # leader → sim (uses LEADER_PORT from config)

B — keyboard teleop (prefer headless or no open Control panel)

uv run lerobot-teleoperate \
  --robot.type=so101_mujoco --robot.id=sim_follower \
  --teleop.type=so101_keyboard --display_data=true

Record a sim dataset (pipeline practice only)

uv run lerobot-record \
  --robot.type=so101_mujoco --robot.id=sim_follower \
  --teleop.type=so101_keyboard \
  --dataset.repo_id=${HF_USER}/so101_mujoco_demo \
  --dataset.num_episodes=10 \
  --dataset.single_task="Pick and place in sim" \
  --display_data=true

Looking ahead

Specialized LeRobot arm use cases

After the binary sorter works, MuJoCo becomes useful for research and teaching variants — still layered on LeRobot data + policies for real evaluation.

Sim-first policy research

Iterate ACT / Diffusion training loops on MuJoCo datasets, then fine-tune on real demos (domain gap remains real).

No-leader classroom kits

Keyboard or phone teleop + real follower — or keyboard + MuJoCo when hardware is scarce.

Reachability / cell design

Use the MuJoCo viewer (CLI · 16) to place bins inside the ~38 cm workspace before locking the table layout.

Multi-task / language arms

Same MuJoCo practice loop, then SmolVLA / VLA on real multi-task demos — see Policy Cheatsheet.

Safety / recovery scripts

Replay (CLI · 15) on real hardware after sim dry-runs — never skip real-cam evaluation.

Kinematics curriculum

Teach FK/IK with the same lengths as the MuJoCo model — Forward & Inverse Kinematics.
