Policy Cheatsheet

Which LeRobot policy to train for the MindGrip binary sorter (match-box → match-box bin; other → reject) on SO-101 — and when to try the next option.

💡
Default for this lab: ACT + one fixed USB cam named front (640×480 @ 30 FPS) · ~40–50 episodes per class (~80–100 total) · train on HF Jobs (a10g-small / a10g-large) or AWS g5 — not on a typical laptop/desktop or Pi. Example run: SUBHENDU/act_2026-09-11_13-54-04 from this dataset.

Decide

60-second decision

Match your goal to a policy. Vision sorting always needs the follower USB cam.

Your situation Pick Why
First binary sorter · cam · cloud GPU ACT Fast, data-efficient, light VRAM — this lab’s path
Same task, demos have many valid grasps / want smoother motion Diffusion Multi-modal actions; heavier / slower than ACT
One model, many verbal task strings SmolVLA Needs language in dataset.task / demos
Research / foundation VLA · large GPU π₀ / π₀-FAST / π₀.₅ Overkill for simple binary sort; A100-class
No USB camera Don’t train a vision sorter Use teleop / replay only, or add front cam first
⚠️
Without a USB camera: ACT / Diffusion / SmolVLA / π-family will not solve match-box vs reject. Joint-only teleop and lerobot-replay still work for hardware checks (CLI · 7 / 15).
Policies

Cards for this lab

Primary stack first; advanced options only after ACT works on your table.

Recommended
ACT

Action Chunking Transformer — predicts short action chunks from front images + joint state. Best first policy for binary sort.

type=act · ~2–6 GB VRAM · HF a10g-small
Recommended
Diffusion Policy

Denoising over action sequences — better when demos have several valid grasps / place paths.

type=diffusion · ~8–14 GB · longer than ACT
Advanced
SmolVLA

Small vision–language–action. Use when one policy must follow different task strings.

type=smolvla · language required · cloud GPU
Explore
π₀ / FAST / π₀.₅

Large flow-matching VLAs. Research / transfer — not the first MindGrip milestone.

type=pi0 / pi0_fast / pi05 · A100-class

ACT detail

  • With cam: best default for match-box vs reject, then colour / shape extensions.
  • Without cam: not a practical visual sorter.
  • Train length (this lab): ~10k steps on ~50 episodes worked on HF Jobs a10g-small (~1–2 h class on A10G/L4 for 50–100 demos).
  • Rule of thumb: think ~5–10 epochs over the dataset; if loss is flat early, collect better / more demos before chasing huge step counts.

Scenarios

Use case → policy

Primary MindGrip task first; extensions after ACT works.

Binary match-box vs reject

ACT (+ cam). Diffusion only if demos are highly multi-modal. No cam → not solvable.

Colour / shape sorting

Same pipeline as binary · ACT first · keep one fixed front view.

Recycling / warehouse pick-to-bin

ACT; SmolVLA if the bin is chosen by language instruction.

Many verbal tasks, one model

SmolVLA (or larger VLA). Needs task text in every episode.

Hardware bring-up only

No train yet — teleop (CLI · 7/8) and replay (CLI · 15).

Hub pretrained → your arm

Advanced (π-family / X-VLA). Still need the camera views the checkpoint expects.
